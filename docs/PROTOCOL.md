# Najik client ↔ server contract (v1)

This is the single source of truth for the REST API and the WebSocket protocol.
`backend/` implements it and `mobile/` consumes it. Change this file first, then both sides.

Conventions:
- Every ID is a UUID string (v4, or v7 where the server generates time-ordered IDs).
- Every timestamp is an ISO-8601 UTC string with milliseconds, e.g. `2026-10-07T09:41:00.123Z`.
- JSON keys are `snake_case`.
- The base path is `/api/v1`. Production is HTTPS-only. The WebSocket endpoint is `/ws/v1/` and production is WSS-only.

## 1. Errors (REST)

Every non-2xx response has this shape:

```json
{ "error": { "code": "invalid_credentials", "message": "Human readable", "details": { "field": ["msg"] } } }
```

Status codes:

| Status | `code` | Meaning |
| --- | --- | --- |
| 400 | `validation_error` | `details` holds per-field errors |
| 401 | `not_authenticated` / `token_expired` / `token_invalid` / `session_revoked` | |
| 403 | `forbidden` | |
| 404 | `not_found` | |
| 409 | `conflict` | e.g. `username_taken` |
| 429 | `rate_limited` | the `Retry-After` header is set |
| 5xx | `server_error` | never leaks internals |

The client refreshes tokens on 401 `token_expired`. It treats `token_invalid` and `session_revoked` as a forced logout.

## 2. Objects

**`ice_servers`** in the `call.invite`/`call.accept` acks and in `call.incoming` is the plain array (`IceServers.ice_servers`). The object form below is only what `GET /calls/ice-servers` returns.

```jsonc
// PublicUser
{ "id": "uuid", "username": "arjun", "display_name": "Arjun", "avatar_color": "#7C5CFF", "created_at": "..." }

// Me = PublicUser + { "email": "a@b.c" | null }

// Presence
{ "user_id": "uuid", "online": true, "last_seen_at": "..." | null }

// Message
{
  "id": "uuid",                 // server id
  "client_id": "uuid",          // generated by the sender; idempotency key, unique per (sender, client_id)
  "conversation_id": "uuid",
  "sender_id": "uuid",
  "seq": 42,                    // per-conversation, strictly increasing, gap-free, starts at 1
  "kind": "text" | "ping" | "call",
  "body": "hello 👋",           // "" for ping/call
  "meta": {},                   // call: {"call_id","media":"audio"|"video","outcome":"completed"|"missed"|"declined"|"cancelled"|"failed"|"busy","duration_sec":12}
  "created_at": "..."
}

// Conversation (always 1-to-1)
{
  "id": "uuid",
  "peer": PublicUser,
  "last_message": Message | null,
  "last_seq": 42,
  "unread_count": 3,
  "my_read_seq": 39,
  "peer_delivered_seq": 42,     // watermark: peer devices have received every message with seq <= this
  "peer_read_seq": 40,          // watermark: peer has read every message with seq <= this
  "updated_at": "..."
}

// Call
{ "id": "uuid", "caller_id": "uuid", "callee_id": "uuid", "media": "audio" | "video",
  "state": "ringing" | "active" | "ended", "created_at": "...", "answered_at": null, "ended_at": null,
  "end_reason": null | "completed" | "missed" | "declined" | "cancelled" | "failed" | "busy" | "answered_elsewhere" | "timeout" }

// IceServers
{ "ice_servers": [ { "urls": ["stun:turn.example.com:3478"] },
                   { "urls": ["turn:turn.example.com:3478?transport=udp", "turn:turn.example.com:3478?transport=tcp", "turns:turn.example.com:5349?transport=tcp"],
                     "username": "1696000000:uuid", "credential": "base64-hmac" } ],
  "ttl_sec": 3600 }
```

Message status on the client is **derived**, never stored per message:

| Status | Condition |
| --- | --- |
| `sending` | local, not acked |
| `failed` | send gave up |
| `sent` | has `seq` |
| `delivered` | `seq <= peer_delivered_seq` |
| `read` | `seq <= peer_read_seq` |

Watermarks only move forward. The server ignores any regression.

## 3. REST endpoints

All endpoints require `Authorization: Bearer <access>` unless marked *public*.

### Auth & sessions
| Method | Path | Body | Response |
| --- | --- | --- | --- |
| POST | `/auth/register` *public* | `{username, display_name, password, email?, device}` | 201 `{user: Me, tokens}` |
| POST | `/auth/login` *public* | `{username, password, device}` | 200 `{user: Me, tokens}` |
| POST | `/auth/refresh` *public* | `{refresh}` | 200 `{tokens}` |
| POST | `/auth/logout` | `{}` | 204 (revokes the current session) |
| POST | `/auth/password` | `{current_password, new_password}` | 204 (revokes all *other* sessions) |
| GET | `/auth/sessions` | | 200 `{results: Session[]}` |
| DELETE | `/auth/sessions/{id}` | | 204 |
| POST | `/auth/sessions/revoke-others` | | 204 |

Field rules and token behaviour:
- `device = {device_id: uuid (stable per install), platform: "ios"|"android", name: "Pixel 8", app_version: "1.0.0"}`.
- `tokens = {access, refresh, access_expires_at, refresh_expires_at}`. The access token lasts 15 min and the refresh token 30 days.
- `Session = {id, device_name, platform, app_version, created_at, last_active_at, ip_country?: null, current: bool}`.
- The access JWT claims are `sub` (user id), `sid` (session id), `jti`, `exp`, `iat` and `type: "access"`.
- **Refresh rotates.** Each refresh returns a new refresh token and invalidates the old one.
  - If an already-rotated refresh token is presented again (a reuse), the whole session is revoked.
- Logging in with a `device_id` that already has an active session for that user replaces the old session.
- Username: `^[a-zA-Z0-9_.]{3,24}$`, case-insensitive unique, stored lowercase.
- Display name: 1–48 characters, trimmed. Password: 8–128 characters, checked with Django's password validators.

### Users
| Method | Path | Notes |
| --- | --- | --- |
| GET | `/users/me` | `Me` |
| PATCH | `/users/me` | `{display_name?, email?}` |
| DELETE | `/users/me` | `{password}`. Deletes the account (required by App Store and Play), then 204 |
| GET | `/users/search?q=ar&limit=20` | `{results: PublicUser[]}`. `q` has at least 2 characters, prefix-matches username/display_name and excludes self |
| GET | `/users/{id}` | `PublicUser` |

### Conversations & messages
| Method | Path | Notes |
| --- | --- | --- |
| GET | `/conversations?cursor=&limit=30` | Ordered by `updated_at` desc. Returns `{results: Conversation[], next_cursor}`. Conversations with no messages yet are omitted |
| POST | `/conversations` | `{user_id}`, get-or-create. 200 or 201 `Conversation` |
| GET | `/conversations/{id}` | `Conversation` |
| GET | `/conversations/{id}/messages?before_seq=&after_seq=&limit=50` | `{results: Message[] (ascending seq), has_more}`. See paging rules below |
| POST | `/conversations/{id}/messages` | `{client_id, body}`. REST fallback for `message.send`. Idempotent: the same `client_id` returns the same message with 200 |
| POST | `/conversations/{id}/read` | `{seq}`. REST fallback for the read receipt |
| GET | `/presence?user_ids=a,b,c` | `{results: Presence[]}`. Only for users you share a conversation with |

Paging rules for the messages endpoint:
- With `before_seq`, it pages history backwards.
- With `after_seq`, it syncs forwards and returns the oldest-first page.
- With neither, it returns the latest page.
- `limit` is at most 100.

### Ping
| Method | Path | Notes |
| --- | --- | --- |
| POST | `/conversations/{id}/ping` | `{client_id}`, REST fallback for `ping.send`. Rate-limited. Returns `Message` (kind `ping`) |

### Calls
| Method | Path | Notes |
| --- | --- | --- |
| GET | `/calls/ice-servers` | `IceServers`. Short-lived TURN credentials (TURN REST API, HMAC-SHA1 with a shared secret) |
| GET | `/calls?cursor=` | Call history `{results: Call[] + peer, next_cursor}` |
| GET | `/calls/{id}` | `Call`. Participants only |
| POST | `/calls/{id}/metrics` | Quality summary from the client. Returns 202 |

The metrics body: `{rtt_ms_avg, jitter_ms_avg, packet_loss_pct_avg, bitrate_kbps_avg_up, bitrate_kbps_avg_down, video_quality_changes, reconnects, duration_sec, network_type, selected_video_quality, selected_audio_quality}`.

### Devices / push
| Method | Path | Notes |
| --- | --- | --- |
| PUT | `/devices/push-token` | `{provider: "fcm"|"apns"|"apns_voip", token}`. Bound to the current session; upsert |
| DELETE | `/devices/push-token` | `{provider}` |

### Ops (public, not under `/api/v1`)
- `GET /healthz`: liveness. Returns 200 `{"status":"ok"}` with no dependency checks.
- `GET /readyz`: readiness. Checks the DB and Redis, then returns 200, or 503 `{"status":"degraded","checks":{...}}`.
- `GET /metrics`: Prometheus. Only served when `METRICS_ENABLED=true`, and is expected to be blocked at the proxy.

## 4. WebSocket protocol

URL: `wss://<host>/ws/v1/`. Frames are JSON text.

Every frame has this envelope:

```jsonc
{ "type": "message.send", "id": "client-req-id (optional)", "data": { ... } }
```

- A client frame that carries `id` gets exactly one reply: `{"type":"ack","id":"…","ok":true,"data":{…}}` or `{"type":"ack","id":"…","ok":false,"error":{"code","message"}}`.
- Server pushes have no `id`.
- Frames larger than 64 KiB are rejected with close code `4009`.

### 4.1 Connection lifecycle

The token is never sent in the URL, because URLs end up in proxy logs.

1. The client connects and must send `{"type":"auth","id":"1","data":{"token":"<access>"}}` within **10 s**. Otherwise the server closes the socket with `4001`.
2. On success the server acks with `{user_id, session_id, server_time, heartbeat_sec: 25}`.
3. The client sends `{"type":"hb"}` every `heartbeat_sec`, and the server replies `{"type":"hb"}`. An `hb` that carries an `id` gets back `{"type":"hb","id":…}`, not an ack.
   - A further `auth` frame on an open socket swaps in a refreshed access token without reconnecting. The server does not close sockets when the access token expires.
   - A new connection counts as `active` until the client sends `app.state`, so the client sends it right after the auth ack.
   - If no frame arrives for `2 × heartbeat_sec`, the server closes the socket.
   - If no `hb` reply arrives within 10 s, the client treats the socket as dead and reconnects.
4. Reconnection uses exponential backoff with full jitter: base 0.5 s, cap 30 s.
   - It reconnects immediately when the network comes back or the app returns to the foreground.
5. After a (re)connect, the client resyncs:
   - It fetches `GET /conversations` (first page).
   - For each conversation that is cached locally and has `last_seq` greater than the local max seq, it fetches `messages?after_seq=<local max>` until `has_more=false`.
   - It flushes its outbox (unacked sends, which are idempotent by `client_id`).
   - It re-subscribes to presence.
6. The client sends `{"type":"app.state","data":{"state":"active"|"background"}}` on AppState changes. A user counts as **online** while at least one of their connections is `active`.

Close codes:

| Code | Meaning | Client action |
| --- | --- | --- |
| `4001` | auth timeout or missing auth | reconnect |
| `4003` | token expired | refresh the token, then reconnect |
| `4004` | token invalid or session revoked | log out, do not reconnect |
| `4008` | rate limited | back off ≥ 5 s |
| `4009` | frame too large or malformed | reconnect |
| `1001` | server going away | reconnect |

### 4.2 Client → server

| type | data | ack data |
| --- | --- | --- |
| `auth` | `{token}` | see 4.1 |
| `hb` | – | (`hb` reply) |
| `app.state` | `{state}` | – |
| `message.send` | `{conversation_id, client_id, body}` | `{message}`. Idempotent per `client_id` |
| `message.delivered` | `{conversation_id, seq}` | – |
| `message.read` | `{conversation_id, seq}` | – (also implies delivered) |
| `typing` | `{conversation_id, state: "start"\|"stop"}` | – |
| `presence.subscribe` | `{user_ids: [..≤200]}` | `{presence: Presence[]}`. Replaces this connection's subscription set |
| `ping.send` | `{conversation_id, client_id}` | `{message}` |
| `call.invite` | `{call_id, callee_id, media}` | `{call, ice_servers}` |
| `call.ringing` | `{call_id}` | – (callee device is ringing) |
| `call.accept` | `{call_id}` | `{call, ice_servers}` |
| `call.decline` | `{call_id}` | – |
| `call.hangup` | `{call_id, reason?: "completed"\|"cancelled"\|"failed"}` | – |
| `call.signal` | `{call_id, signal}` | – |
| `call.media_state` | `{call_id, audio_muted, video_enabled}` | – |

Rules:
- **`message.send`**: `body` is 1–4000 characters after trimming. Control characters other than `\n` and `\t` are stripped.
- **`call.invite`**: `call_id` is generated by the client so that the push and the socket agree.
- **`call.signal`**: `signal` is one of:
  - `{type:"offer", sdp}`
  - `{type:"answer", sdp}`
  - `{type:"candidate", candidate:{candidate, sdpMid, sdpMLineIndex, usernameFragment?}}`
  - An offer may also carry `iceRestart: true`. Any other unknown field is rejected.
  - `{type:"renegotiate"}`
  - `{type:"quality", video:"auto"|"144p"|"240p"|"360p"|"480p"|"720p"|"1080p", audio:"auto"|"low"|"medium"|"high"}`. The receiver asks the sender to cap what it sends.
  - The serialized signal is at most 16 KiB.

| `message.receipt` | `{conversation_id, user_id, delivered_seq, read_seq}` |

| `call.ended` | `{call_id, reason}` |
| `call.signal` | `{call_id, signal}` |

### 4.4 Call state machine (server-authoritative, held in Redis, persisted in Postgres)

```
invite ──► ringing ──accept──► active ──hangup/peer lost──► ended
              │ decline/cancel/timeout(45 s)/busy ─────────► ended
```

Busy and ringing:
- A user who is already in a ringing or active call gets an immediate `call.ended{reason:"busy"}` for any new invite.
- The callee is rung on **all** their connections plus a push (FCM high-priority data, and APNs VoIP when a token exists).
  - The first `call.accept` binds the call to that session.
  - Every other callee device gets `call.ended{reason:"answered_elsewhere"}`.

Relaying signals:
- After accept, `call.signal` is relayed **only** between the caller's session and the bound callee session.
- Signals for unknown or ended calls, or from non-participants, are dropped with `ack ok:false code:"call_not_found"`.
- `call.signal` is only accepted while the call is `active`. The caller therefore sends its offer after receiving `call.accepted`.
- `call.accepted` also reaches the accepting session itself. Any device whose `session_id` differs treats it as answered elsewhere.
- The 45 s ring timeout ends the call with reason `timeout`, and the call-log message records outcome `missed`.
- Busy: if the caller is already in a call, the `call.invite` ack fails with code `busy`. If the callee is busy, the ack succeeds with an ended call and a `call.ended{reason:"busy"}` event follows.
- The server does not resend `call.incoming` after a reconnect. Clients confirm a pending call with `GET /calls/{id}`.

Network loss:
- If a participant's connections all drop during an active call, the server waits **30 s** before ending the call with `failed`.
- Reconnecting within that window (any connection of the same session) cancels the timer.
  - The client then performs an ICE restart: it sends a new offer with `iceRestart`.

Call log:
- When a call ends, the server writes a `kind:"call"` message into the conversation and emits `message.new`.

### 4.5 Rate limits

Rate limits are enforced in Redis and shared across instances.

| Action | Limit |
| --- | --- |
| login | 5/min per (IP, username) and 30/min per IP |
| register | 5/hour per IP |
| refresh | 30/min per session |
| `message.send` | 20 per 10 s per user (burst), 600/hour |
| `typing` | 20 per 10 s |
| `ping.send` | 1 per 5 s per (sender, conversation), 30/hour per sender |
| `call.invite` | 6/min per user |
| `call.signal` | 300/min per call per user |
| search | 30/min |

A rate-limited WebSocket request gets `ack ok:false code:"rate_limited", retry_after_sec`. Repeated abuse closes the socket with `4008`.

## 5. Push payloads

All pushes are data-first so that the app controls what it presents.

| Kind | FCM (Android) | APNs (iOS) |
| --- | --- | --- |
| Message | data `{type:"message", conversation_id, message_id, sender_name, preview}`, priority high. The notification carries the title/body, and `tag=conversation_id` collapses per chat | alert + `thread-id=conversation_id` |
| Ping | `{type:"ping", conversation_id, sender_name}` | |
| Incoming call | data-only `{type:"call.incoming", call_id, caller_id, caller_name, media, expires_at}`, priority high, TTL 45 s | the VoIP push holds the same payload; with no VoIP token, a time-sensitive alert |
| Call ended | `{type:"call.ended", call_id, reason}`, so the device stops ringing | |

Pushes:
- **Message**: only sent when the recipient has no `active` connection.
- **Message preview**: controlled by user setting (default: show).
- **Incoming call**: always sent, even if the callee is online.

Push tokens that come back as invalid (`UNREGISTERED`, `BadDeviceToken`) are deleted.
